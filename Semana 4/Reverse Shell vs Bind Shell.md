# Tipos de Shell
Cuando hablamos de shell es prácticamente la línea de comandos que nos permitirá interactuar con la maquina que comprometamos y que evidentemente debe de ir en el payload que se va a inyectar a través del exploit, los principales tipos que uno se puede topar es la Reverse Shell y la Bind Shell.

# Bind Shell
En esta nos conectamos a la máquina victima, es decir la maquina victima pone un puerto a la escucha y nosotros nos conectamos a ella, por lo que la conexión es de la maquina atacante hacia la maquina victima, pero este uso es muy puntual y generalmente se ve cuando ya comprometimos el sistema y como ya lo comprometimos podemos hacer esta configuración por ejemplo para tener otra sesión en el sistema comprometido, pero esta técnica como tal para intrusiones como primera instancia no es tan efectiva porque como cualquier elemento de seguridad como IDS, IPS o meramente firewalls pueden bloquear este tipo de conexiones porque cualquier firewall frenaría cualquier intento tan descarado de conexión. 

# Reverse Shell
Para solucionar lo de la Bind Shell está Reverse Shell, lo que hace Reverse Shell es que invierte la dirección de la conexión, es decir aquí la maquina victima se conecta a nosotros, podría no tener sentido pero evidentemente la máquina victima se conecta a nosotros sin hacerlo ella voluntariamente, porque generalmente esto se consigue después de explotar una vulnerabilidad e inyectar un payload,  y el payload generalmente contiene una Shell reversa que se enviará a nuestra maquina por  un puerto que determinemos y evidentemente esta es mucho mas difícil de detectar y bloquear ya que de forma general las conexiones salientes son comúnmente permitidas por la mayoría de políticas implementadas en los elementos de seguridad como un firewall y es por eso que para la mayoría de los casos es mejor hacer una shell reversa a un puerto común digamos el puerto 443 porque digamos que un firewall ve esta petición saliente al puerto 443 pues no le parecería muy sospechosa porque perfectamente la maquina podría estar accediendo a por ejemplo una pagina web en concreto pero si detecta por ejemplo una conexión saliente al puerto 65534 pues a lo mejor no pasa nada o la bloquee porque no es un puerto común.

# Resumen
Bind -> Escucha y espera una conexión

Mientras que Reverse activamente establece una conexión, esto del lado de la victima y lo que haríamos en la mayoría de casos es establecer una reverse shell, posiblemente la herramienta a usar para recibir dicha shell sino es mediante una herramienta automatizada posiblemente sea Netcat.
Reverse -> Lanza y espera una conexión

Hay mas formas de generar una shell tanto Bind como Reverse en diferentes lenguajes de programación, se puede hacer de manera manual o uno se puede apoyar de extensiones o recursos web como revshells.com donde principalmente para shell reversas únicamente pones tu IP y le puerto donde esperas recibir dicha shell además de seleccionar el lenguaje de programación o de scripting en el cual está hecho la shell, además de poder cambiar el tipo de shell si queremos que sea reversa o de tipo bind, si se quiere que sea generada por MSFVenom o para HoaxShell que es para temas de evasión de Windows Defender.

# Forward Shell o Port Forward Shell
Este concepto no es como tal una Shell como la Reverse o la Bind es mas se refiere a una técnica donde el trafico de una shell es redirigido a través de un intermediario para alcanzar así su destino final y podemos emplearlo cuando hacemos es un reenvío de puertos (esto podría verse mejor en un curso de metasploit para hacking ético) por lo que a esta técnica se le llama así.
